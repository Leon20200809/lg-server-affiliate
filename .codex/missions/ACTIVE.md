# MISSION 003｜ターゲット・価値訴求・TOP導線の精錬

## 0. 任務名

**任務：XServerアフィリエイトサイトのターゲットを明確化し、TOPページの訴求・構成・記事導線をその読者向けに精錬する**

---

# 1. 背景

MISSION 001でサイトを公開し、MISSION 002でA8.netの正式アフィリエイト導線を実装した。

現在は、

- Astro
- Cloudflare Workers
- 独自ドメイン
- 技術記事
- A8.net正式テキスト広告
- 300×250バナー広告

まで動作している。

MISSION 003では新機能を増やさない。

今回の目的は、

> **「誰にXServerを紹介するサイトなのか」
> 「XServerを持つことで読者がどう変わるのか」**

を明確にし、サイト全体のメッセージを一本に通すこと。

---

# 2. このサイトの最上位目的

このサイトは技術ブログではない。

**XServerのアフィリエイトサイトである。**

ただし単純に、

- 料金が安い
- 高速
- 容量が多い
- WordPressが簡単

といったスペック比較だけで売るサイトにはしない。

このサイトの差別化は、

> **実際にXServerを本番環境として使い、
> WordPress・PHP・SSH・WP-CLI・Composer・Node.js・Git・CI/CD・Laravelなどを動かしてきた実体験**

にある。

---

# 3. 第一ターゲット

MISSION 003では第一ターゲットを以下に固定する。

> **ローカル環境ではWordPressやPHPなどを使って「動くもの」を作れるようになったが、まだ本番環境の経験が少ない人。**

さらに具体的には、

- WordPressをLocal等では構築できる
- PHPをローカルでは動かせる
- 自分でWebサイトや小さなWebアプリを作れる
- Gitを少し使える
- 作ったものをインターネット上へ公開したい
- 他人に使ってもらえる状態にしたい
- SSHや本番サーバーはまだ少し怖い
- 初案件でいきなり本番環境を触ることに不安がある
- 公開後の修正・デプロイを効率化したい

といった層を想定する。

---

ここでは、

**本番環境を持つ意味**

---

# 9. VALUEで伝えること

最低限以下の思想を含める。

### 9-1. 公開する

ローカルで作った、

- WordPressサイト
- PHPプログラム
- Webアプリ

をインターネット上で実際に動かす。

---

### 9-2. 本番を知る

公開すると、

- PHPバージョン
- PATH
- ファイル権限
- SSH
- サーバーディレクトリ
- Composer
- Node.js
- Git
- 本番固有の設定

など、ローカルだけでは見えにくかった問題が現れる。

これを自分の環境で経験する。

---

### 9-3. 実際のサービスとして動かす

用途とサーバー制約が合えば、

- Laravel等で作成したWebアプリ
- 自分用ツール
- 小規模な業務アプリ

などを実際に稼働させることも可能。

ただし、

> XServerならあらゆるアプリを動かせる

とは表現しない。

共有レンタルサーバーであることを前提に、

> **用途・必要機能・サーバー制約が合う場合**

という条件を守る。

---

### 9-4. 改善を速くする

GitやCI/CD等を利用すると、

```text
修正
↓
テスト
↓
Git
↓
push
↓
本番反映
```

という開発運用へ進める。

目的は「CI/CDを使うこと」ではない。

> 手作業によるミスを減らし、変更を安全かつ速く反映する

こと。

# 12. ROADMAP

現在の、

> XServerで実際に取り組んだこと

は活かす。

ただし単なる機能紹介ではなく、

**本番環境へ慣れていく成長ルート**

として見せることを検討する。

例：

```text
STEP 1
WordPressを本番へ公開する

STEP 2
SSH / WP-CLIを使う

STEP 3
PHP / Composer / Node.jsを整える

STEP 4
Git / rsyncで反映する

STEP 5
CI/CDで変更を自動反映する

STEP 6
Laravel等のWebアプリを動かす
```

全STEPの記事がまだ存在しなくてもよい。

存在しない記事への架空リンクは作らない。

# 15. 「案件にビビらない」という価値

以下の思想は利用してよい。

> 案件で初めて本番環境を触るのではなく、自分の環境で先に経験しておく。

ただし、

> XServerを使えば案件で絶対困らない

などの断定はしない。

伝える趣旨は、

> 自分の本番環境を持ち、SSH・デプロイ・ログ確認・設定変更等を経験しておけば、本番環境そのものへの心理的・技術的な抵抗を減らせる。

とする。

---

# 16. 「他人へ価値を提供する」という未来

最終的には、

> 自分で作ったものを、自分以外の人が使える状態へ持っていく

ことを重要な未来として扱う。

例：

```text
自分のPCだけで動く
= 開発物

インターネット上で公開される
= 他人がアクセス可能

継続して動かす
= 運用

改善を続ける
= サービス提供
```

ただし、

> 公開しただけで価値提供になる

とは断定しない。

**利用者の目的を満たすものを安定して提供すること**

まで含めて価値提供と考える。

---

# 17. XServerを紹介する理由

XServerを「唯一の正解」として紹介しない。

今回伝える理由は、

- 実際に長期間利用している
- WordPressを運用している
- SSHが利用できた
- WP-CLIを利用できた
- PHP / Composerを扱えた
- Node.js環境を整えられた
- Git / rsyncを利用できた
- GitHub Actionsによるデプロイを経験した
- Laravelアプリの公開を経験した

など、**実体験を持って説明できるから**である。

---

# 18. 向いていないケースも隠さない

信頼性を優先する。

以下のような場合は、

- 常時起動する特殊プロセスが必要
- OSレベルで自由な設定が必要
- root権限が必要
- 高度なインフラ制御が必要
- アプリ要件が共有レンタルサーバーの制約と合わない

等、別の選択肢が適する可能性がある。

MISSION 003では詳細比較ページまでは作らなくてよい。

必要なら、

> 用途によってVPSやクラウド等が適する場合もある

程度を明記する。

# 19. 事実と表現の規律

## 事実

実際に経験・確認した内容のみ、

> 実際に使った
> 実際に動かした

と表現する。

## 推定

今後可能と思われる内容は断定しない。

## 参考

一般的な説明と本人の実体験を混同しない。

## 不明

現在確認できないXServerの仕様・料金・制限は推測で書かない。

# 25. Git / Cloudflare

```text

git diff
```

```text

git push
git remote変更
```

```text
作れる
↓
公開できる
↓
本番で動かせる
↓
失敗から学べる
↓
改善できる
↓
自動化できる
```
