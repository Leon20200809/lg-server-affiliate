# MISSION 004｜FigmaでTOPページの高忠実度デザインを作成する

## 0. 任務名

**任務：XServerアフィリエイトサイトのTOPページを、Figmaで高忠実度デザイン（モックアップ）として再設計する**

---

# 1. 背景

このプロジェクトは、XServerを実際に使った経験をもとにした**アフィリエイトサイト**である。

現在のTOPページは、構成・内容・訴求軸はかなり良い方向へ進んでいるが、司令官判断として次の課題がある。

> **内容は強いが、見た目・世界観・ブランド感でまだ損をしている。**

そのため、MISSION 004ではコード実装へ進む前に、Figma上でTOPページの見た目を先に設計する。

---

# 2. 最重要目的

今回の最優先目的は以下。

> **世界観と見た目を上げたい。ブランド感・高級感・差別化重視。**

これは単なる情報整理ではなく、**「このサイトは他と違う」「この人は実戦で語っている」**という印象を見た瞬間に持たせるための任務である。

---

# 3. 対象範囲

今回の対象は**TOPページのみ**。

以下は今回の対象外。

- 記事一覧ページ
- 記事詳細ページ
- aboutページ
- privacyページ
- 実装コード変更
- Cloudflare / GitHub / A8設定変更

---

# 4. 絶対残す要素

以下は必須要素として維持する。

- ヒーローの主コピー

  > **ローカルでは作れる。次は、本番で動かせる人へ。**

- VALUEの主コピー

  > **作ったものを「自分のPCの中」で終わらせない。**

- A8広告

- ロードマップ構造

文言の細かな見せ方や配置調整はしてよいが、思想は変えない。

---

# 5. 変えてよい要素

以下は積極的に改善してよい。

- セクション順
- 配色の濃淡
- 余白
- カードデザイン
- CTAの見せ方
- タイトルの見せ方
- レイアウトの強弱
- セクションの背景切替
- 視線誘導
- アイコン・装飾・ライン・パネル表現
- 図解的な見せ方

---

# 6. 目指す印象

今回のデザインが目指す印象は以下。

- 実戦的
- 信頼感
- 少し高級
- 技術者向け
- 地味すぎない

加えて、以下の空気感を意識する。

- 「量産アフィリエイトサイト」には見えない
- 「実務で使っている人のノート・実践記録」の雰囲気がある
- ただの学習サイトではなく、**本番環境・公開・運用・改善**まで見据えている
- 堅すぎず、軽すぎず、安っぽくない
- 技術者が見て気分が上がる

---

# 7. デザインの方向性

以下の方向性で検討する。

## 7-1. ブランドの核

このサイトは、単なるサーバー比較サイトではない。

> **自分で作ったものを、ローカル環境の中で終わらせず、
> 本番で動かし、改善し、価値提供へつなげるための実践サイト**

である。

そのためデザインでも、

- 学習
- 実験
- 実践
- 運用
- 改善
- 自動化

の空気が感じられることが望ましい。

---

## 7-2. 世界観キーワード

必要に応じて以下をヒントにしてよい。

- modern technical editorial
- premium engineering
- hands-on field notes
- practical lab
- structured system
- calm but sharp
- professional minimal
- blueprint / terminal / grid / documentation motif
- production / deployment / infrastructure nuance

ただしSFすぎる未来感や、意味のない飾り過多は避ける。

---

## 7-3. 色の方向性

ベースは現行サイトの方向を引き継ぐ。

- ダークネイビー
- 淡いブルーグレー
- 白
- 落ち着いたブルーアクセント

必要なら濃淡を調整してよい。

狙いは、

> **技術感 + 信頼感 + 少し高級**

である。

---

# 8. 画像の扱い

司令官は、無料素材をそのまま使うのではなく、**サイトに合う画像生成も視野に入れている**。

そのため今回のFigmaデザインでは、以下のどちらかで対応してよい。

## 方式A

画像なしで成立する、タイポグラフィ・レイアウト中心のデザイン

## 方式B

将来的に画像生成で差し替える前提で、
Heroや要所に**画像プレースホルダーまたはアートディレクション前提の領域**を置く

---

## 画像を使う場合の条件

以下のような方向性がサイトに合う。

- 実務感のあるデスク環境
- ノートPC
- ターミナル / コード / エディタの雰囲気
- 設計図・構造化・グリッドを感じる抽象表現
- WordPress / PHP / Laravel / CI/CD を直接ロゴ化せず、抽象的に示唆する表現
- 「本番へ出す」「実装を積み上げる」空気感

NG寄り:

- 安っぽいストックフォト感
- ビジネスマンの握手
- 派手すぎる未来SF
- 抽象すぎて意味不明
- 明るすぎるカジュアル系
- 実在ブランドロゴだらけ

# 10. TOPページで表現すべき内容

構成・情報は以下を基準とする。

## 10-1. Hero

- 主コピー
  **ローカルでは作れる。次は、本番で動かせる人へ。**
- 本番環境へ慣れる価値
- 実戦的な印象
- CTA
- できれば「実務の入口」「公開」「運用」の空気感

---

## 10-2. ローカルと本番の違い

- ローカルでは動いたが、本番では別の問題が出る
- PHPバージョン、PATH、権限、SSH、デプロイなど
- 読者の不安を可視化する

ここは説明文だけでなく、**視覚的に伝わる表現**を検討してよい。

---

## 10-3. VALUE

- **作ったものを「自分のPCの中」で終わらせない。**
- 公開する
- 本番を知る
- 安全に速く改善する

この3段階が分かりやすく、しかも見栄えよく見えること。

---

## 10-4. 自分の本番環境を持つ意味

- 案件で初めて触る前に練習できる
- 自分の環境で試せる
- 失敗して学べる
- 改善と自動化につなげられる

---

## 10-5. XServerを紹介する理由

- 実際に使ってきた
- 説明できる
- WordPressだけでなくSSH / WP-CLI / PHP / Composer / Node / Git / CI/CD / Laravel等に触れてきた

ここは「スペック紹介感」より**実体験の説得力**が出る見せ方が望ましい。

---

## 10-6. ロードマップ

構造は残す。

- WordPressを本番へ公開する
- SSH / WP-CLIを使う
- PHP / Composer / Node.jsを整える
- Git / rsyncで反映する
- CI/CDで変更を自動反映する
- 条件に合うWebアプリを動かす

単なるカード列より、**成長の段階・進行感・攻略感**が出る表現を歓迎する。

---

## 10-7. 記事導線

- 実体験記事
- 本番で困ったことから整理した記事

現行より、**「読みに行きたくなる感」** を高める。

---

## 10-8. FIT

- 向いている人
- 別の選択肢が適する要件

このサイトの信頼感に関わるため、読みやすく整理する。

---

## 10-9. CTA / A8広告

A8広告は必須。

ただし「いかにも広告」感を強めるのではなく、

> **自然に押したくなる最終導線**

として見せる。

CTA領域は今より洗練してよい。

---

# 11. 実装を意識した制約

これはFigma任務だが、最終的にはWebへ実装する前提がある。

そのため以下を守る。

- 極端に複雑すぎる表現は避ける
- CSSで再現可能性が低すぎる特殊表現は避ける
- PCファーストだが、スマホでも崩れにくい構造を意識する
- 画像に依存しすぎない
- 文量が多少増減しても破綻しにくい設計にする
